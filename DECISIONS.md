# ReadFluent — DECISIONS

Dated, short, reversible. Newest at the bottom. Each entry says what was decided, why, and what would change it.

## 2026-10-01 — Working defaults for the open questions

These unblock the build. None are final; the owner decides.

**Pricing: free 50-page samples, paid upgrade for 100/200.**
Matches the example in the product spec and the template's subscription plumbing (RevenueCat). Implemented as a config table, not hard-coded, so it can change without a rebuild. Change if the owner picks another model.

**Accounts: optional.**
Reading works signed-out. Signing in (email OTP, Google, Apple) is required to buy and to sync progress and flashcards across devices. Progress is stored locally first and synced when signed in. Change if the owner wants accounts mandatory.

**Offline: explicit download only.**
Same rule as the template: nothing persists unless the reader downloads a book version. Unit of download is one version (book + level + length).

**Launch platform: iOS and Android via the Capacitor wrapper, one codebase.**
The wrapper makes both cheap. Store submission order is the owner's call.

**Translation: not in v1. English only.**
Colour-matched words need a second language, so that tool ships with translation. The data model reserves a per-language field on word entries so adding it later is not a migration.

## 2026-10-01 — Scale shapes the architecture

**Content is generated by a pipeline, not authored by hand.**
2,430 versions and ~283,500 pages. The pipeline writes, CEFR-checks, and rejects/regenerates. A version is publishable only when every page passes. The reading app consumes the pipeline's output as static JSON; no AI calls at read time.

**Photo plan is an open owner decision with a recommended default.**
~54,000 photos minimum if shared across levels and reused across lengths. Hand-shot is not realistic. Recommend: generated imagery with a consistent style per book, a human spot-check per book, and one shared photo set per book (the 200-page set; shorter lengths pick from it).

**Dictionary cards are generated per word, cached.**
Root, form, pronunciation, meaning, stored once per word and level-agnostic, not per page.

## 2026-10-01 — working defaults for the open questions

These unblock the build. None is final; the owner decides.

- Pricing: free 50-page samples, paid upgrade for 100 and 200 pages (the example in the brief). Built as a config table in `lib/plan.ts`, not hard-coded. A version someone has started stays open. Change if the owner picks another model.
- Accounts: optional. The template already signs every new device in anonymously (`proxy.ts`), so reading needs no account. Signing in is for buying and for sync. Change if the owner wants accounts mandatory.
- Progress sync: `sync_docs` documents, last-write-wins per document (the template's `0005_sync.sql`). Not relational tables.
- Offline: explicit download only, one cache bucket per version (book + level + length). Nothing persists unless the reader downloads it.
- Launch platforms: iOS and Android from one Capacitor wrapper. Which store goes first is the owner's call.
- Translation: not in v1, English only. Colour-matched words need a second language, so that tool ships with translation. Word entries are keyed per language from the start so adding one is not a migration.

## 2026-10-01 — scale and content

- Content is generated by a pipeline, not authored by hand: 2,430 versions, ~283,500 pages. A version publishes only when every page passes every gate. The app reads static JSON; it never calls a model.
- Content is served from storage, not bundled. Mental Stint compiles its books into the app (`lib/books/parts`); that cannot hold 8.8M words and would also bloat every native build.
- Photos and audio go in object storage behind a CDN, default Supabase Storage (already in the stack). Revisit after M2 measures real sizes: a rough estimate is ~54,000 photos and ~20–30 GB of audio.
- "Say it again, slowly" is playback rate (0.7×, pitch preserved), not a second recording. Halves audio storage and generation cost.
- Photos (owner, 1 Oct 2026): generated, 200 per book, 54,000 in all. Level never changes the pictures. The 200-page version uses all 200; the 100-page uses every 2nd; the 50-page every 4th, so the sets nest and a book is illustrated once. Each book has a 200-beat storyboard written once; each version writes its page k to cover the story up to its photo's beat, so all nine versions share one story skeleton. One consistent style per book, human spot-check per book.
- Phone storage (owner, 1 Oct 2026): the installed app is a thin shell under 2 MB; books stream from the server; only an explicit download stores anything. Photos are stored once per book (not per version), audio is an optional part of a download, and there is a storage readout and per-download remove. Sizes in SPEC.md §7 are estimates until M2.
- Page length: one constant, `PAGE_WORDS = { min: 28, max: 35 }`, used by the validator, the pipeline and the tests. The owner said "25, 27 to 35, something like that"; 28–35 is the spec's number. Loosening to 25 is a one-line change.
- Dictionary (replaces the earlier per-version words map): one library-wide dictionary keyed by headword, generated once per word however many books use it, so common words cost nothing after the first. A book downloads only its slice. A word that means something different in one book gets a per-book sense override.
- Pipeline goes before the polished reader (M2, not M10). It is the one risk that can change the product; the reader should be built against real content.
- CEFR gate, initial design, to be calibrated on the M2 pilot: vocabulary coverage against a published CEFR word list per band, plus mean sentence length, plus a second-opinion model judgement, and a hard failure on any of the three. Thresholds are set from the pilot, not guessed now.
- "Inspired by" books are written from the pipeline's own brief (ideas, structure, a distinct title), never from the source text, so there is no source text to retell. An overlap check against the brief runs as a gate.
- Health books: the "not medical advice" line is a validated field on the book, not copy typed per screen. The validator fails a health book without it.

- i18n: M0 ships no strings layer at all. The shell has five short English literals, and the template's mechanism (`lib/i18n/strings.ts`, 20 languages, 40 key files) is all Mental Stint wording. Add a `t()` layer when translation is scheduled, not before.

- Credentials: nothing is copied from Mental Stint. New Supabase project, Vercel project, RevenueCat app, iOS and Android keystores. Keystores are generated outside the repo and backed up; `*.keystore`, `*.jks`, `*.p8`, `*.p12` and `.env*` are in `.gitignore` from M0.

## 2026-10-01 — Preview slice (before M1)

- Order changed at the owner's request: a visible slice comes before M1 so the app can be looked at and edited on a real URL. Everything else in SPEC.md §10 is unchanged; the pipeline is still M2, before any real book text.
- The preview content is deliberately not the real contract: one book, 12 scenes, three levels, compiled into the app from `lib/preview/catalog.ts`, which CLAUDE.md forbids for real content. It is temporary and is deleted when M1 loads content from storage. Every length (50, 100, 200) opens the same 12-page sample and the header chip says "preview".
- The text is an original retelling written for the preview, not a quotation of the novel. All 36 pages (3 levels × 12) are 28–35 words, checked by `tests/unit/preview-content.test.ts` against the one `PAGE_WORDS` constant in `lib/content/limits.ts`.
- Photos are generated placeholders (a drawn landscape per scene, captioned "Photo placeholder"), not images: real ones come from the pipeline (M2), and spending the owner's image-generation credits was not asked for.
- Measured, not assumed: the first layout cut the text off mid-sentence on a 375×667 phone (a banner plus a 4:3 photo plus 20px type). Fixed by moving the preview note into the header chip and end screen, using a 16:10 photo capped at 34% of the screen height, and 19px/1.5 type. All 36 pages now fit with no scrolling at 375×667, 360×640 and 390×844.
- The pager is native CSS scroll-snap, so swiping feels like the phone's own and costs no gesture code. Photos are mounted only for the current page and its two neighbours either side (5 at most), which is what lets a 200-page version stay light.
- "Where you got to" and "last level and length" are two small device-stored documents (`lib/progress.ts`), read through `useSyncExternalStore` so the first render matches the server's. Both become `sync_docs` in M8.
- Vercel with no environment variables runs in local mode (no database, no sign-in), which is all the preview needs. The Vercel project should track this branch as its production branch until the work is merged (see DEPLOY.md).
- `package.json` pins `engines.node >= 22` so Vercel builds with the Node version the tests ran on.

## 2026-10-01 — M0 (seed and strip)

- Deferred from M0 to the milestone that rewires them, rather than copied dead: `lib/sync/*` (M8, tied to Mental Stint's six stores), `lib/srs/*` (M7, imports its card formats), `lib/books/narration.ts` and `lib/voice.ts` (M6), `lib/books/offline*.ts` and `downloads.ts` (M9), the email-code form in `components/Account.tsx` (M8, built on its glass/aura styling and string tables). All stay readable at the pinned commit `8a7f13c`. `lib/auth/native.ts` needed `safeNext` and `OAuthProvider` from two of those files, so they moved to `lib/auth/next.ts` and `lib/auth/providers.ts`.
- `public/sw.js` is rewritten as a shell-only worker (about 170 lines, down from 672), not trimmed: it stores only SHELL paths and the build's hashed files, never touches cross-origin requests (where books, photos and audio will live), and reserves `readfluent-dl-` for M9's download buckets, which a deploy never deletes. Kept from the original: build-named cache, network-first navigations with a timeout, `/api` never cached.
- Migrations are three files, not eight: `0001_init` (users, events, RLS, auth triggers), `0002_plan` (the plan guard, now also covering `plan_product`/`plan_period`), `0003_sync` (`sync_docs` with the server-stamped ordering folded in). `kind` is checked to `progress|word|card|review`; M8 may extend it with a new migration. Proved against a real PostgreSQL 16 with `scripts/prove-sql.sh` (all pass), not only by text checks.
- The webhook no longer retries without `plan_product`/`plan_period`: that fallback existed for a migration that might not have run, and here the columns exist from `0001`.
- Next.js bumped 16.3.4 → 16.3.8 for a critical advisory (RCE in `next/og`, GHSA-vcvr-r3jv-pc5j; this app does not use `next/og`, but a fix existed with no breaking change). Three moderate advisories remain, all inside `@capacitor/cli`'s build-time tooling (`uuid`, `xcode`); npm's only offered fix is a major downgrade, so they stay until Capacitor ships one.
- System font stack for M0 (no `next/font/google`, which fetches at build time and can fail offline or in CI). Typefaces are chosen when the reader is designed (M4); `--font-reading` is a serif stack placeholder.
- `capacitor.config.ts` writes `appId` and `appName` out as literals instead of importing `lib/brand.ts`: the CLI transpiles that one file on its own and a relative import is a risk that cannot be checked off a Mac. `tests/unit/native-identity.test.ts` holds the literals, `lib/brand.ts` and both native projects together.
- `app/layout.tsx` types `children` directly instead of Next's generated `LayoutProps<"/">`: that global only exists after `next typegen`/`build`, so a fresh checkout's `npm run typecheck` failed before CI reached the build step.
- Google OAuth client ids are emptied (`lib/auth/google.json`; `Info.plist` carries a `REPLACE_WITH_…` scheme) and the Apple team id is removed from the iOS project (`ExportOptions.plist` has a placeholder). They identified the other app's accounts. Restoring the same Apple team is one line if it is the same developer account.
- `PRICE` in `lib/plan.ts` is a placeholder (599/3999 pence); pricing is the owner's call. `PAYMENTS_LIVE` is false until M10, so every version is open in the meantime.
- Icons and splash are generated placeholders (an open book on paper) by `scripts/make-icons.sh` from `public/icon.svg`, rasterised with Chromium; replace the SVGs and rerun for a real identity.
- The health page's "Clear the cache" button now spares the `readfluent-dl-` download namespace, so M9's downloads are never wiped by a troubleshooting button.
- "Reading online leaves nothing behind" is true of the app's own storage (Cache Storage), checked in a real browser: the shell caches, a non-shell page does not. The browser's ordinary HTTP cache is separate (Next sends `s-maxage` plus an ETag, and Chrome serves a stale copy when offline) and the OS may evict it; CLAUDE.md now says exactly that.
- `tests/unit/identity.test.ts` fails the suite if the old name, domains, storage prefix, Google project, or Apple team id reappear anywhere outside SPEC/DECISIONS/CLAUDE. M0's grep criterion is therefore enforced on every commit, not run once.
